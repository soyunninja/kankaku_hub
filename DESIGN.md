# Design System: kankaku-hub

## Overview

**Creative North Star: "The Measurement Ledger"**

The Measurement Ledger describes the incumbent kankaku-hub dashboard, not a new product brand. Its mood is discreet, precise, and legible: measurements and their reporting context lead, while pink provides a recognizable signal on neutral ground.

Soft and precise components sit in discreet functional layers. Tonal separation carries flat surface hierarchy; control borders and table dividers retain functional boundaries without decorative shadows. Compact tables coexist with more open summary and catalog cards without forcing one density onto every surface.

This is a scan of the current implementation. [PRODUCT.md](PRODUCT.md) supplies the owner-controlled measurement context; it does not authorize a redesign. Frontmatter values are normative for this snapshot; the linked implementation remains the authority when it changes. No visual anti-reference was selected.

**Key Characteristics:**
- Discreet, precise, legible.
- Pink signal on neutral ground in light and dark themes.
- Soft and precise controls; discreet functional layers.

## Colors

**Palette character:** pink signal on neutral ground. Unprefixed tokens are light primitives; `dark-` keys are the matching dark primitives. Dark mode inherits `avatar-foreground`, which deliberately stays near-black in both themes.

### Primary

Primary pink is exactly `oklch(0.580 0.228 1)` in both themes; chart-1 uses the distinct brighter `oklch(0.650 0.228 1)` in both themes. Filled primary labels use the existing contrast-safe white. Light accent surfaces retain their pink tint; dark accent/sidebar-accent surfaces use elevated charcoal with the existing neutral foreground. Small dark links and active navigation labels are neutral, not pink.

Brand `ring`/`sidebar-ring` primitives remain exactly matched to light primary. Focus paint is a separate semantic alias outside the 73 primitive declarations: `--focus-indicator` resolves to `--ring` in light and existing `--foreground` in dark. Explicit focus consumers opt in; full-opacity destructive invalid rings retain priority. Exact primary pink paints at only 2.986:1 against unchanged dark `#292929`, so dark focus and selected-calendar graphics use neutral foreground there. Pink active sidebar icons remain on the passing `#1C1C1C` surface. See [the matched-pink change record](odd/tasks/matched-pink-accents.md).

### Neutral

Light mode uses a `#F9F9F9` canvas with white (`#FFFFFF`) cards. Dark mode uses neutral charcoal surfaces with role-matched light brand accents: estimated canvas `#141414`, cards/sidebar `#1C1C1C`, and elevated popovers/secondary `#292929`. These are approved visual estimates, not sampled reference pixels. Neutral dividers are `#383838`; opaque input strokes are approximately `#989898` for visible control boundaries. Secondary text is approximately `#C1C1C1`, including readable placeholders on the existing 30%-input fills. Foreground `oklch(0.959 0.009 342)` remains unchanged, as do the near-black status foregrounds and fixed avatar-initials foreground. Primary pink fills instead use the corresponding light white foreground. Status and chart-2..5 identity remain unchanged; focus paint and dark calendar selection are neutral for contrast. See [the charcoal change record](odd/tasks/dark-neutral-charcoal-surfaces.md) for its historical scope and [the incremental surface refinement](odd/tasks/neutral-surface-refinement.md) for the current combined intent and verification limits.

### Status and data

Success, warning, and destructive pairs communicate status. The five chart tokens carry theme-aware data identity and also support client avatars. Chart pink is not necessarily the primary-button pink. The stacked chart's final Others series is separately neutral (`#64748b`), not a status token.

**The Semantic Pair Rule.** Use semantic foreground/background pairs from the active theme; chart identity and measurement status are separate meanings.

Source: [declared CSS tokens and theme aliases](web/app/assets/css/tailwind.css), [chart series](web/app/components/charts/StackedBarChart.vue), and [avatar palette](web/app/lib/client-avatar.ts). Extract declarations, not historical palette descriptions. Alias variables are resolved to literal primitives here. Sidecar ramps are generated OKLCH previews only, not project colors or an implemented tonal scale.

## Typography

Inter leads the full CJK-aware sans stack in frontmatter; JetBrains Mono leads the technical stack. These are declared families, not evidence that every font is installed or downloaded. There is no separate display face.

Page titles use the observed xl size, semibold weight, and tight tracking. Dashboard's localized greeting uses the shared reactive auth name, trimmed and safely interpolated at 24px/800 weight above the 20px/600 prefix, or a generic 20px greeting when absent; navigation and export titles remain Dashboard. Other titles are not personalized; KPI values extend the semibold hierarchy to 2xl. Body uses base/sm sizes; compact labels use xs. Ordinary control text is 16px below 768px and 14px at or above 768px; the fixed control-sm recipe describes desktop labels. Buttons use medium weight; ordinary inputs retain inherited text weight. Numeric measurements retain tabular figures rather than changing to a decorative face. Global body features are `cv11` and `ss01`.

Japanese text uses strict line breaking, normal word breaking, and overflow wrapping for long mixed Latin tokens. Paragraphs and list items use line-height (1.8); emphasized Japanese text is not artificially italicized. Preserve the existing narrow-screen KPI adjustment rather than assuming Latin text widths.

Sources: [global typography](web/app/assets/css/tailwind.css), [KPI hierarchy](web/app/components/dashboard/KpiCard.vue), [page title](web/app/pages/unassigned/index.vue), and [control typography](web/app/components/ui/button/index.ts). Sizes and utility defaults come from the installed Tailwind theme, not a custom project scale.

## Layout

The headerless desktop shell has a borderless, rounded sidebar (15rem), inset 24px from the canvas with height `calc(100dvh - 48px)` and a flexible independently scrolling content region. Sidebar navigation scrolls independently above a non-shrinking footer: search and the read-only badge precede the avatar/account row at the bottom. Theme and language controls live only on the existing Settings page, reachable through navigation; the footer does not duplicate them. Page titles are authoritative; no topbar height or breadcrumb space is reserved. Main padding is the `shell` token, increasing to `shell-md` at md. Repeated gap-4 spacing uses the documented utility value, not an invented bespoke rhythm. Dashboard's KPI and client/project breakdown grids use gap-6 (24px) at every breakpoint.

Below md, an ordinary-flow Open menu button in main content opens the left sheet (16rem shell override), with the same bottom footer and account row last. It is not a fixed or sticky replacement header. The mobile navigation Sheet also overrides its right border to zero; page-detail Sheets and control boundaries remain unchanged. Utility targets are at least 44px; keyboard focus returns to the menu trigger on Escape or after a palette opened from the Sheet closes. Breakpoint relocation restores only focused footer controls, never page/filter or BODY focus. Default responsive thresholds are sm (640px), md (768px), and lg (1024px). Keep existing responsive grids and horizontal table overflow; these are context-dependent patterns, not a universal fixed-width page grid.

Sources: [shell](web/app/layouts/default.vue), [sidebar footer](web/app/components/app-shell/SidebarFooter.vue), and [entries tables](web/app/pages/entries/index.vue). The imported Tailwind defaults supply spacing and breakpoints; no custom breakpoint configuration is asserted.

## Elevation & Depth

**Flat functional layers:** cards are borderless and shadowless in both themes. The Entries filter layer is not a Card and has no surface frame. Controls, menus, popovers, dialogs, sheets, active tabs, and toasts have no decorative elevation. Semantic control/overlay borders and table dividers remain. Focus and invalid-state rings remain visible; their zero-offset spread is an indicator, not decorative elevation. The shell has no persistent header, translucent topbar, or decorative footer elevation.

The sidecar records no decorative shadows and preserves the observed motion durations. Dialogs fade/zoom over (200ms); sheets slide with (500ms) opening and (300ms) closing durations. These are existing behaviors, not a new motion grammar.

Sources: [card](web/app/components/ui/card/Card.vue), [input](web/app/components/ui/input/Input.vue), [dialog](web/app/components/ui/dialog/DialogContent.vue), and [sheet](web/app/components/ui/sheet/SheetContent.vue).

## Shapes

**Soft and precise:** the base radius produces the sm/md/lg/xl mappings in frontmatter. Standalone buttons and fields use a shared 16px radius; navigation uses md; default cards use xl; dialogs use lg. Badges are fully rounded. Existing client/project catalog articles are softer still, using Tailwind's rounded-3xl utility; their decorative outer borders are removed without normalizing them into default Card shapes. Clients detail measurement mini-boxes are also borderless; section dividers remain.

Sources: [radius aliases](web/app/assets/css/tailwind.css), [badges](web/app/components/ui/badge/index.ts), and [catalog articles](web/app/pages/projects/index.vue).

## Components

**Buttons:** default primary, secondary, legacy outline, ghost, destructive, and link variants are already implemented. All action buttons are physically borderless, including native actions and as-child links. Semantic checkbox, radio, switch and combobox widgets keep their field boundaries unless explicitly overridden by a scoped filter style. Ordinary text and icon buttons are 44px high with 12px horizontal padding and text-base/md:text-sm typography. Segmented controls are one 44px outer group with 4px inset and 36px, 12px-radius internal buttons. Explicit xs/icon-sm/icon-xs calendar and dense table variants remain compact. Primary hover remains opaque to preserve white-label contrast; secondary and ghost/outline retain their semantic treatments. Shared link buttons use neutral foreground in both themes, including secondary surfaces where light primary text would fall below 4.5:1. Measurement-table buttons explicitly opt out of decorative hover through `noHover`, preserving each variant's resting colors. Focus uses a three-pixel full-opacity semantic focus indicator without a physical button border (light pink, dark neutral); invalid rings are opaque destructive with explicit focused-invalid priority, and disabled states remain distinct. Dark outline uses translucent input color rather than light background. The scoped toolbar variant uses opaque muted backgrounds and normal foreground at rest and on hover in both themes: Dashboard/Entries period and Export, Tasks Completed history, Unassigned Assign group, and Entries More filters. These triggers retain ordinary 44px geometry and semantic focus/invalid indicators; Assign group retains no-hover.

**Cards and tables:** the default Card is a borderless, shadowless column with gap and vertical padding (24px), plus separately padded header/content slots. Tasks list, Entries results and both assignment queues use these shared defaults: 24px vertical Card padding and 24px horizontal CardContent padding, matching Dashboard's by-client card. Entries filters live outside a Card: the filter grid and More panel have transparent backgrounds, no outer padding, border or radius, while retaining logical gaps. The Entries mode selector and Tasks Board/List selector match catalog List/Grid groups (muted, rounded-2xl, secondary active buttons). Tables scroll internally when needed. Rows, cells, sort controls, links and actions have no decorative hover effects; dividers, selected-state fills, tooltips and keyboard-focus indicators remain.

**Inputs:** shared ordinary inputs, selects and period triggers use muted borderless fields, 16px corners and 44px height. Full-opacity focus and invalid rings remain visible. Composite command/attachment search wrappers own the surface and focus indicator; their embedded inputs are transparent. Calendar internals, semantic checkbox/radio/switch widgets and multiline textarea geometry are excluded. Catalog total counts appear in localized search placeholders rather than title subtitles. Base text becomes sm at md. Preserve placeholder, selection, focus, invalid, and disabled treatments rather than styling only the resting field.

**Entries period:** a clean visit and Reset use the last 30 inclusive local calendar days. Explicit dates retain one-sided or bounded intent; All time is an explicit shareable choice. The baseline period is not an advanced-filter count. Narrow triggers may truncate visible dates while keeping the full accessible label and calendar icon.

**Badges:** compact, fully rounded labels with default, secondary, outline, destructive, success, and warning variants. Success/warning use their own foreground pairs. Only linked badges receive hover behavior; primary-badge hover is opaque, and its semantic focus indicator is full-opacity. Nonpink status variants retain their existing treatments; status labels are not automatically interactive.

**Sidebar navigation:** medium-weight sm labels and compact inset padding are unchanged. The active icon uses the exact shared `sidebar-primary` pink. Light active labels rest pink and use existing neutral `sidebar-foreground` on hover, including keyboard focus while hovered; dark active labels use existing neutral `sidebar-foreground` for normal-text contrast. Inactive icons stay explicitly `sidebar-foreground`. Links rest on transparent backgrounds and use neutral `muted` hover fills, never pink selection fills. The shared desktop/mobile links expose `aria-current="page"` for matching routes (including parent routes on detail pages) and a two-pixel semantic focus indicator (light pink, dark neutral) with a sidebar-colored offset.

**Overlays:** dialogs are centered, bordered, lg-rounded surfaces; sheets attach to an edge. Retain existing close controls and open/closed transitions. Sidecar component snippets are standalone style previews, not functional replacements for Vue/Reka interactions.

## Do's and Don'ts

### Do:

- Do preserve paired light/dark semantic foregrounds, status meanings, and visible keyboard focus.
- Do keep measurement columns tabular and preserve the existing compact table spacing.
- Do preserve localized wrapping and Japanese paragraph breathing room.

### Don't:

- Don't substitute chart-series colors for status semantics.
- Don't replace measurement-table default gutters with full-bleed padding overrides or duplicate those gutters inside the table.
- Don't describe missing or uncertain measurements as confirmed zero.
