# Design System: kankaku-hub

## Overview

**Creative North Star: "The Measurement Ledger"**

The Measurement Ledger describes the incumbent kankaku-hub dashboard, not a new product brand. Its mood is discreet, precise, and legible: measurements and their reporting context lead, while pink provides a recognizable signal on neutral ground.

Soft and precise components sit in discreet functional layers. Borders and tonal separation carry everyday hierarchy; stronger overlay shadows distinguish temporary surfaces. Compact tables coexist with more open summary and catalog cards without forcing one density onto every surface.

This is a scan of the current implementation. [PRODUCT.md](PRODUCT.md) supplies the owner-controlled measurement context; it does not authorize a redesign. Frontmatter values are normative for this snapshot; the linked implementation remains the authority when it changes. No visual anti-reference was selected.

**Key Characteristics:**
- Discreet, precise, legible.
- Pink signal on neutral ground in light and dark themes.
- Soft and precise controls; discreet functional layers.

## Colors

**Palette character:** pink signal on neutral ground. Unprefixed tokens are light primitives; `dark-` keys are the matching dark primitives. Dark mode inherits `avatar-foreground`, which deliberately stays near-black in both themes.

### Primary

Signal pink (`primary`) and soft pink (`dark-primary`) identify primary actions. The `accent` pair supplies tinted interaction surfaces; sidebar equivalents preserve navigation semantics. `ring` supplies focus color, not a second brand accent.

### Neutral

Light white surfaces and near-black text become subtly pink/plum-tinted dark ground, card, and popover layers. `secondary`, `muted`, borders, input strokes, and their foregrounds remain distinct semantic roles, even where light literals coincide. Do not flatten the dark system into generic gray.

### Status and data

Success, warning, and destructive pairs communicate status. The five chart tokens carry theme-aware data identity and also support client avatars. Chart pink is not necessarily the primary-button pink. The stacked chart's final Others series is separately neutral (`#64748b`), not a status token.

**The Semantic Pair Rule.** Use semantic foreground/background pairs from the active theme; chart identity and measurement status are separate meanings.

Source: [declared CSS tokens and theme aliases](web/app/assets/css/tailwind.css), [chart series](web/app/components/charts/StackedBarChart.vue), and [avatar palette](web/app/lib/client-avatar.ts). Extract declarations, not historical comments: the stale teal description is not palette authority. Alias variables are resolved to literal primitives here. Sidecar ramps are generated OKLCH previews only, not project colors or an implemented tonal scale.

## Typography

Inter leads the full CJK-aware sans stack in frontmatter; JetBrains Mono leads the technical stack. These are declared families, not evidence that every font is installed or downloaded. There is no separate display face.

Page titles use the observed xl size, semibold weight, and tight tracking; KPI values extend the semibold hierarchy to 2xl. Body uses base/sm sizes; compact labels use xs. Controls use medium-weight sm text. Numeric measurements retain tabular figures rather than changing to a decorative face. Global body features are `cv11` and `ss01`.

Japanese text uses strict line breaking, normal word breaking, and overflow wrapping for long mixed Latin tokens. Paragraphs and list items use line-height (1.8); emphasized Japanese text is not artificially italicized. Preserve the existing narrow-screen KPI adjustment rather than assuming Latin text widths.

Sources: [global typography](web/app/assets/css/tailwind.css), [KPI hierarchy](web/app/components/dashboard/KpiCard.vue), [page title](web/app/pages/unassigned/index.vue), and [control typography](web/app/components/ui/button/index.ts). Sizes and utility defaults come from the installed Tailwind theme, not a custom project scale.

## Layout

The desktop shell has a fixed sidebar (15rem), a sticky header (3.5rem), and a flexible independently scrolling content region. Main padding is the `shell` token, increasing to `shell-md` at md. Repeated gap-4 spacing uses the documented utility value, not an invented bespoke rhythm.

Below md, navigation moves into a left sheet (16rem shell override). Default responsive thresholds are sm (640px), md (768px), and lg (1024px). Keep existing responsive grids and horizontal table overflow; these are context-dependent patterns, not a universal fixed-width page grid.

Sources: [shell](web/app/layouts/default.vue), [header](web/app/components/app-shell/Header.vue), and [entries tables](web/app/pages/entries/index.vue). The imported Tailwind defaults supply spacing and breakpoints; no custom breakpoint configuration is asserted.

## Elevation & Depth

**Discreet functional layers:** borders and tonal separation do most of the work. Cards retain the subtle default small shadow; outlined controls and inputs use the extra-small shadow. Dialogs and sheets use stronger large shadows, not floating elevation on every surface. The sticky header adds a translucent background and backdrop blur.

The sidecar records the expanded installed Tailwind shadow values and observed motion durations. Dialogs fade/zoom over (200ms); sheets slide with (500ms) opening and (300ms) closing durations. These are existing behaviors, not a new motion grammar.

Sources: [card](web/app/components/ui/card/Card.vue), [input](web/app/components/ui/input/Input.vue), [dialog](web/app/components/ui/dialog/DialogContent.vue), and [sheet](web/app/components/ui/sheet/SheetContent.vue).

## Shapes

**Soft and precise:** the base radius produces the sm/md/lg/xl mappings in frontmatter. Buttons, inputs, and navigation use md; default cards use xl; dialogs use lg. Badges are fully rounded. Existing client/project catalog articles are softer still, using Tailwind's rounded-3xl utility; do not normalize them into default Card shapes.

Sources: [radius aliases](web/app/assets/css/tailwind.css), [badges](web/app/components/ui/badge/index.ts), and [catalog articles](web/app/pages/projects/index.vue).

## Components

**Buttons:** default primary, secondary, outline, ghost, destructive, and link variants are already implemented. Standard text buttons are (36px) high; xs/sm/lg and icon sizes remain available. Leading SVGs reduce horizontal padding. Primary hover reduces background opacity; secondary and ghost/outline use their existing semantic treatments. Focus uses a ring-colored border and a three-pixel half-opacity ring; invalid and disabled states remain distinct. Dark outline uses translucent input color rather than light background.

**Cards and tables:** the default Card is a bordered column with gap and vertical padding (24px), plus separately padded header/content slots. Entries and assignment tables deliberately override vertical padding to zero and content padding to zero. Do not reintroduce default whitespace into those table containers.

**Inputs:** transparent light background, translucent input-colored dark background, semantic border, md corners, and (36px) height. Base text becomes sm at md. Preserve placeholder, selection, focus, invalid, and disabled treatments rather than styling only the resting field.

**Badges:** compact, fully rounded labels with default, secondary, outline, destructive, success, and warning variants. Success/warning use their own foreground pairs. Only linked badges receive the source hover behavior; status labels are not automatically interactive.

**Sidebar navigation:** medium-weight sm labels, compact inset padding, and active sidebar-accent pairs. Inactive links use an 80%-opacity foreground and adopt the accent pair on hover. The source does not add a custom nav focus ring; preserve keyboard focus rather than claiming a new treatment is implemented.

**Overlays:** dialogs are centered, bordered, lg-rounded surfaces; sheets attach to an edge. Retain existing close controls and open/closed transitions. Sidecar component snippets are standalone style previews, not functional replacements for Vue/Reka interactions.

Sources: [button variants](web/app/components/ui/button/index.ts), [card slots](web/app/components/ui/card/CardContent.vue), [input](web/app/components/ui/input/Input.vue), [badge variants](web/app/components/ui/badge/index.ts), and [navigation](web/app/components/app-shell/SidebarNav.vue). Snippets inherit real CSS variables with light fallbacks; dark behavior depends on inherited active-theme values.

## Do's and Don'ts

### Do:

- Do preserve paired light/dark semantic foregrounds, status meanings, and visible keyboard focus.
- Do keep measurement columns tabular and preserve the existing compact table spacing.
- Do preserve localized wrapping and Japanese paragraph breathing room.

### Don't:

- Don't substitute chart-series colors for status semantics.
- Don't restore default card padding to tables that intentionally override it.
- Don't describe missing or uncertain measurements as confirmed zero.
