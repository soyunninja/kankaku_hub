# Use shadcn-vue Combobox across hub

Goal: Replace the hub's native `Select` controls with the shadcn-vue Combobox pattern for every catalog and fixed-choice selector. Owner explicitly chose all controls, including short lists. Preserve each current `v-model` value, options, All/None placeholder behavior, disabled state, accessibility name, and client→project/task dependencies. No changes to unrelated native date inputs; Entries date filters have their own Date Picker task.

Research: `web/app/components/ui/select/Select.vue` currently wraps native `<select>`; ~20 usages across 8 page/component files. No local Combobox exists, but `reka-ui` is a direct dependency and official shadcn-vue Combobox documentation (https://www.shadcn-vue.com/docs/components/combobox) composes Reka UI primitives. Existing E2E specs use native `selectOption`, `select`/`option` locators and must migrate with the UI, not be deleted. The repo's `components.json` config uses the New York style and `@/components/ui` alias.

Constraints: This is cross-cutting and high review workload; phase sequentially, keep writes single-threaded, stop if registry CLI would overwrite existing UI files. No schema/sync change, commit/push/build/deploy without explicit request. Worktree `feat/cache-hit-display` is already dirty with prior authorized features; preserve all unrelated files. Before T1, inspect CLI/registry output in a disposable context or obtain exact asset list, and bind allowed paths. No `pnpm dlx ... add` blindly into the repository.

Decision after read-only map: all ~20 callers share a simple `Select.vue` API. Implement shadcn-vue Combobox *inside* this existing adapter instead of rewriting eight caller files mechanically; this preserves dependent filters and reduces review workload. The visible widgets become Combobox immediately, with E2E interactions migrated in T2/T3. Official CLI in a disposable preview generated 11 Combobox Vue primitives plus an index barrel; use direct SFC imports because standalone TypeScript LSP does not resolve `.vue` re-exports (Nuxt typecheck does). No new package dependency. Existing :3002 app is stale; a fresh isolated :3003/:8093 stack was used for browser checks and then stopped without purging evidence.
