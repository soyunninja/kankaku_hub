# Projects grid design

## Objective
Apply the Clients screenshot-inspired presentation to Projects: heading/count, local search, grid/list toggle, and three desktop/two mobile project cards. No page-specific sidebar. Keep Projects' client filter, sortable table, detail route and CRUD actions.

## Scope and constraints
- Edit `web/app/pages/projects/index.vue`, `web/i18n/locales/{en,es,ja}.json`, focused `web/tests/projects-page.test.ts`, and `web/app/components/ui/select/Select.vue` only for optional visual slots used by this client filter. Preserve the default Select rendering for all other callers. Do not change schema, composables, sort utilities, existing Clients/Entries diffs, or unrelated tasks.
- Project records have no icon field. User explicitly chose the associated client's favicon/avatar in project cards instead of the generic folder icon; now make that grid avatar much smaller (`xs`). Add the client's favicon/initials before each name in the client filter options and selected trigger, but not for the `All` option. Use the existing `ClientAvatar` fallback and preserve Combobox text-value/search/keyboard semantics. In grid cards put project name and edit/archive actions together on the first row (actions to the right), with a second row containing small client favicon, client name and conditional ` / code`; follow with active status and existing time/cost totals. At mobile widths, allow title/actions to reflow without overlap.
- Search locally by project name/code/client name, composing with the existing client filter and sort; keep archived projects visible. Grid default; preserve sortable table as list and the existing client filter as a visible labeled control without adding a sidebar.
- Cards navigate to `/projects/:id` via a keyboard-operable detail affordance separate from writer-only edit/archive buttons. Preserve `canWrite` gates, totals fallback and truncated warning, loading and empty/no-match states. Two columns at mobile width and three at desktop, including skeletons; avoid narrow-card overflow.
- Technical artifacts English, localized strings in existing language files. No commit, push, or deployment without explicit authorization.
